# Architecture Review
Generated: 2026-10-07T16:42:42.094Z
Score: 68/100

## Summary
Small, well-documented Toss mini-app (return-deadline board) with a sensible components/lib/pages split and no circular dependencies. Weaknesses are a drifted, unused contract.ts that contradicts the real types, repeated haptic/SDK-guard helpers, mixed import styles, and a few unused template components and exports that add noise.

## Issues
### Critical
- [consistency] src/lib/contract.ts is an auto-generated 'interface contract' that contradicts the real implementation. DeadlineRule is a union of objects here but a string union in types.ts. ChecklistItem uses text/completed here and label/done in types.ts. ItemStatus is 'active'|'archived' here and 'active'|'returned'|'kept' in types.ts. DeadlineInfo uses `dday` here and `dDay` in types.ts. BoardSection and ArchiveReason also differ. Function signatures differ too: formatKoreanDate, addItem and validateForm return different shapes. The file is not imported by the code shown, so it is a misleading second source of truth. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/deadline.ts, src/lib/itemsStore.ts, src/lib/validateForm.ts / Fix: Delete contract.ts or regenerate it from the real types (e.g. `export type * from './types'`). If tooling requires it, add a type-level test that the contract matches the implementation.

### Warnings
- [duplication] The same guarded haptic helper (try { Promise.resolve(generateHapticFeedback(...)).catch(() => {}) } catch {}) is copy-pasted in at least five places with slightly different type unions: fireHaptic in BottomCTA, haptic in ChecklistSection, ItemFormSheet and Result, and an inline version in FloatingTabBar. Home.tsx also imports generateHapticFeedback and probably does the same. — Files: src/components/BottomCTA.tsx, src/components/ChecklistSection.tsx, src/components/ItemFormSheet.tsx, src/pages/Result.tsx, src/components/FloatingTabBar.tsx, src/pages/Home.tsx / Fix: Create src/lib/haptic.ts exporting a single `haptic(type)` that accepts the SDK's HapticFeedbackType and swallows errors, like analytics.ts, review.ts and share.ts already do for their SDKs. Replace all local copies with it.
- [consistency] Inconsistent storage access. itemsStore.ts calls window.localStorage directly with its own try/catch and error classes. storage.ts offers a generic getItem/setItem/removeItem wrapper used only by review.ts, where setItem throws and getItem swallows errors. Home uses sessionStorage inline with its own try/catch. There are three storage patterns and two different error policies. Also, itemsStore.getItem(id) (items) and storage.getItem(key) share a name, and Result imports `getItem` from itemsStore, which invites mix-ups. — Files: src/lib/itemsStore.ts, src/lib/storage.ts, src/lib/review.ts, src/pages/Home.tsx, src/pages/Result.tsx / Fix: Make storage.ts the one low-level layer (with a `session` variant and consistent error semantics) and build itemsStore on top of it. Rename itemsStore.getItem to getItemById.
- [consistency] Mixed import styles. Pages and components import siblings via relative paths ('../components/...', '../lib/utils') but lib modules via the '@/' alias, often inside the same file (Home.tsx, Result.tsx, ItemFormSheet). Components also mix relative and alias lib imports (Amount uses '../lib/utils', ChecklistSection uses '@/lib/utils'). Quote style also varies: double quotes in the template files and single quotes in app code. — Files: src/pages/Home.tsx, src/pages/Result.tsx, src/components/Amount.tsx, src/components/CountUp.tsx, src/components/ChecklistSection.tsx, src/components/PageShell.tsx, src/components/ScreenScaffold.tsx / Fix: Pick one convention (prefer the '@/' alias for cross-folder imports, relative only for same-folder) and enforce it with ESLint import rules and Prettier.
- [structure] lib/ mixes concerns. types.ts holds domain types plus runtime constants, UI copy (MESSAGES, RULE_NOTICE, COST_LINE, ARCHIVE_LABEL), a storage key and the ruleSourceLine function. deadline.ts mixes date math, sorting, summary text and formatting, and its imports from types and utils run in a single file of 166+ lines. checklistPresets.ts hosts the generic `newId` helper used by itemsStore. The `seq` counter is module state. Generic components (Card, Amount, StateView) sit beside feature components (ChecklistSection, ItemFormSheet) in one flat folder. — Files: src/lib/types.ts, src/lib/deadline.ts, src/lib/checklistPresets.ts, src/components/ChecklistSection.tsx, src/components/ItemFormSheet.tsx / Fix: Split types.ts into types.ts (pure types), constants/copy.ts (messages, labels, notices) and storageKeys. Move newId to utils. Split deadline.ts into date.ts (pure date math), deadline.ts (rules) and board.ts (sort/summarize). Group components into components/ui (template) and components/<feature>.

### Suggestions
- [duplication] Amount and CountUp share the same wrapper span styling (inline-block, nowrap, tabular-nums) and the same Typography type alias. Amount should be a thin case of CountUp, or both should use a common NumberText. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract a shared `NumberText` (or have CountUp render <Amount value={display} .../>) and share the Typography type.
- [dead_code] Several template components and utilities have no consumer in the shown pages: FloatingTabBar, MiniBar, Sparkline, CountUp, Amount, TossPurchase, TossRewardAd (plus its reward-ad.css), and utils.cn/formatCurrency. Only the TdsGallery dev page could reference some of them. Unused components stay in the source tree and TossPurchase/TossRewardAd pull SDK surface area into type-checking. — Files: src/components/FloatingTabBar.tsx, src/components/MiniBar.tsx, src/components/Sparkline.tsx, src/components/CountUp.tsx, src/components/Amount.tsx, src/components/TossPurchase.tsx, src/components/TossRewardAd.tsx, src/lib/utils.ts / Fix: Remove what the app does not need or move it to a clearly marked template/ui-kit folder. Because of tree-shaking, unused modules cost nothing in the bundle, so this is a clarity issue. Keep only what the product plans to use.
- [dead_code] Redundant or unused exports and imports. deadline.ts re-exports formatNumber from utils (`export { formatNumber }`) while Home and Result import it from utils. Types DeadlineRule, FormField and ChecklistItem appear in imports where they may be unused (e.g. `DeadlineRule` and `FormField` in ItemFormSheet, `Badge`, `Switch`, `Spacing` and `Paragraph` in ChecklistSection). - [consistency] Error-handling patterns differ. itemsStore uses typed errors (StoreReadError, StoreWriteError, ItemNotFoundError) thrown to callers. analytics, share and review swallow every error. The components use try/catch with instanceof checks (ChecklistSection.run) and local Phase state machines (Home and Result define near-identical `Phase` unions with separate loading/error handling). Result has an extra 'missing' state. — Files: src/lib/itemsStore.ts, src/components/ChecklistSection.tsx, src/pages/Home.tsx, src/pages/Result.tsx / Fix: Extract a small shared `useItemsLoader` / `useItem(id)` hook returning a typed phase, and a `runWrite(op)` helper that maps StoreWriteError to a toast, so Home, Result, ChecklistSection and ItemFormSheet stop repeating it.
- [naming] Naming inconsistencies. The type field is `dDay` while helper names use `ddayLabel`. File names mix PascalCase components with `StateView.tsx` (exports EmptyState/LoadingState) and `BottomCTA.tsx` (exports SubmitFooter), so file names do not match their main export. The 'pages/__TdsGallery.tsx' name has a double-underscore prefix. The `ItemStatus` value 'archive' vs 'archived' appears across BoardSection ('archive') and the contract ('archived'). Comments and docs are in Korean while identifiers are English, which is fine, but the mixed scaffolding comments (@ai-factory / @AI:) add noise. — Files: src/components/StateView.tsx, src/components/BottomCTA.tsx, src/lib/types.ts, src/lib/deadline.ts, src/pages/__TdsGallery.tsx / Fix: Rename files to match their primary exports (e.g. EmptyState.tsx/LoadingState.tsx, SubmitFooter.tsx), use `dDay` consistently (ddayLabel -> dDayLabel), and unify 'archive'/'archived' vocabulary.
- [consistency] PageShell and Card go to unusual lengths to guard against test mocks (`pick()` on namespaces, `import * as RouterDom/AnalyticsLib/Tds`).
